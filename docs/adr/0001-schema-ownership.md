# ADR-0001: Владение схемой в общих ODM-командах

Статус: Accepted. Дата записи: 2026-10-07.

Пакеты могут готовить индексы и validators собственной явной командой, в том
числе вне ODM metadata. Общий update Doctrine приводит схему к metadata и
может удалить такие ограничения. Принята публичная регистрация владения через
`Ys\LaravelOdm\ODM\SchemaOwnershipRegistry`: общие create/update/drop пропускают
зарегистрированные схемы, а адресный вызов и удаление защищённой базы отказывают
до записи. Это реализует принятый в задаче вариант 2 и политику Q6.

Идентичность схемы определяется фактической базой и коллекцией, разрешёнными
по metadata документа или явно зарегистрированными именами. Альтернативный
mapping не обходит защиту. Несовместимое владение проверяется до изменения
любой схемы. Registry не зависит от Cmf или Taplink.

Отдельный SchemaManager общей команды получает только разрешённый список
metadata. Исходная фабрика DocumentManager сохраняется: runtime, metadata,
proxies/hydrators и прямой SchemaManager владельца доступны полностью.
Алгоритмы индексов, validators, search indexes и опции остаются у upstream
Doctrine; bridge определяет только границу общего обхода и предварительный
отказ. Для схем без регистрации сохраняется исходный SchemaManager.

Регистрация не запускает подготовку, миграции или проверку готовности. Явная
команда остаётся ответственностью владельца; корректность её схемы и deploy
readiness проверяются отдельно. Ручной вызов прямого SchemaManager или MongoDB
не перехватывается. Поэтому защита требует своевременной регистрации provider
и не заменяет операционные правила владельца.

Рассмотренный перенос всех индексов в ODM metadata не сохраняет неизвестные
индексы и правила переходов владельца. Отдельный движок исторических миграций
расширил бы задачу без необходимости. Цена выбранного решения — новый публичный
API интеграции и минимальная версия в зависимых пакетах; публикация и проверка
Registry consumer являются самостоятельными этапами.
